# Яндекс Расписания — серверный шлюз для «Моего ритма»

GitHub Pages не умеет безопасно хранить секреты и запускать серверные функции. Поэтому запросы к Яндекс Расписаниям идут через Cloudflare Worker. API-ключ хранится только в секрете Worker и никогда не попадает в браузер или Git.

## 1. Получить ключ
1. Открой https://developer.tech.yandex.ru/
2. Создай ключ API Яндекс Расписаний и активируй его по инструкции Яндекса.
3. Не отправляй ключ в чат, не добавляй его в файлы репозитория и не вставляй в `config.js`.

## 2. Развернуть Worker
1. Открой https://dash.cloudflare.com/ → Workers & Pages → Create → Worker.
2. Создай Worker, например `my-rhythm-rasp`.
3. Вставь содержимое файла `backend/rasp-worker.js` в редактор Worker и нажми Deploy.
4. В настройках Worker → Settings → Variables and Secrets → Add → Secret создай:
   - Name: `YANDEX_RASP_API_KEY`
   - Value: твой ключ Яндекс Расписаний.
5. Добавь переменную `APP_ORIGIN` со значением адреса GitHub Pages сайта, чтобы ограничить CORS. Если не настроить, Worker использует Origin запроса.

## 3. Подключить Worker к сайту
Открой `assets/js/config.js` и укажи адрес Worker:
```js
window.MY_RHYTHM_RASP_API_BASE = "https://ИМЯ-WORKER.ТВОЙ-АККАУНТ.workers.dev";
```
Сохрани изменение в GitHub. Ключ API сюда не добавлять.

## API Worker
- `GET /api/health` — проверка сервиса и наличия секрета.
- `GET /api/stations?q=львов` — поиск пригородных станций; возвращает точный код Яндекса и подпись.
- `GET /api/search?from=<station-id>&to=<station-id>&date=YYYY-MM-DD` — поиск электричек.

Worker загружает справочник станций Яндекса и кэширует его на шесть часов. Перед поиском проверяет, что оба ID существуют в справочнике. Код станции не генерируется из названия и не переписывается вручную.

## Важно
Данные предоставляются Яндекс Расписаниями. Проверь действующие условия использования и требования к атрибуции перед публичным запуском. API может не предоставлять онлайн-информацию о задержках или фактическом движении.
