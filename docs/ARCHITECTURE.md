# Архитектура проекта «Мой ритм»

## Цель
Сейчас основной интерфейс — статический сайт GitHub Pages. В будущем к нему должен подключаться Telegram-бот без повторной реализации бизнес-логики.

## Принципы разработки
1. Не привязывать правила работы с расписанием, задачами и статистикой только к элементам HTML.
2. Хранить данные в понятных JSON-структурах с устойчивыми идентификаторами.
3. Разделять интерфейс (сайт/бот), прикладную логику и источники данных.
4. В дальнейшем вынести общие операции в серверный API. Сайт и Telegram-бот будут обращаться к одним и тем же endpoint-ам.
5. Не хранить секретные ключи API в браузерном JavaScript или публичном репозитории.

## План перехода к Telegram
- Этап 1: сайт и локальное хранение; расписание РУЗ через обновляемый JSON-кэш.
- Этап 2: серверный слой/API и база данных для аккаунтов и синхронизации устройств.
- Этап 3: Telegram-бот как второй интерфейс к тем же данным и операциям.
- Этап 4: общие уведомления, настройки пользователя и синхронизация сайта с ботом.

## Данные расписания РУЗ
- Источник: `https://ruz.guz.ru/api/`.
- GitHub Actions обновляет `data/ruz/groups.json` и отдельные файлы `data/ruz/YYYY-MM-DD.json`.
- Кэш охватывает текущую дату и следующие 41 день по времени Europe/Moscow.
- Сайт читает кэш с того же домена GitHub Pages, поэтому браузеру не нужно напрямую обращаться к API РУЗ и обходить CORS.
- В ответе РУЗ встречаются занятия групп и потоки с вложенным массивом `groups`; фильтрация должна учитывать оба варианта.
- API может отдавать номер пары, но не время начала/окончания. Не показывать выдуманные часы: таблицу звонков нужно подключить отдельно после проверки официального расписания.

## Ограничения текущей версии
- GitHub Pages и localStorage не обеспечивают аккаунты и синхронизацию между устройствами.
- Кэш РУЗ обновляется по расписанию GitHub Actions; ручной запуск доступен во вкладке Actions.
- Telegram-интеграция потребует серверного компонента, токена бота и защищённого хранения секретов.
